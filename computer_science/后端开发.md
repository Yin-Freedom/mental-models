## 缓存

将经常访问的数据存储在内存中提高性能，减少延迟、网络流量，降低服务器或数据库负载。

### 分布式缓存

- 实现：Redis、Memcached
- 存储位置：独立部署的缓存服务器
- 优点：
- 缺点：有网络请求；需要维护缓存服务
- 应用场景
  - 用户会话信息
  - 热点数据缓存（如商品详情页、热点新闻）
  - 限流、计数器等高并发访问场景

### 对象缓存

- 实现：序列化Java/PHP/Python对象后存入Redis或本地
- 优点：快速恢复业务对象状态
- 缺点：反序列化有一定开销
- 应用场景
  - 电商场景中的商品、用户对象缓存
  - 复杂结构的数据缓存，如聚合数据展示

### 反向代理缓存

- 实现：Nginx、CDN服务（如CloudFlare、阿里云CDN）
- 功能：将服务器响应内容缓存在反向代理服务器或边缘节点

- 优点：减轻源站压力，提高访问速度
- 缺点：控制粒度有限，更新需要主动刷新
- 应用场景
  - 海量用户访问的静态资源（JS/CSS/图片）
  - 面向全国/全球用户的网站内容缓存



## 身份认证

Session（基于 Cookie）：登录成功后，服务端创建 session，并通过 cookie 存储 sessionId。

Token（如自定义 Token + Redis）：登录后生成 token，客户端保存并每次携带，后端根据 token 查 Redis 验证用户身份

JWT（JSON Web Token）：登录后生成自包含的 token，包含用户信息、权限等；无状态，服务端无需存储

OAuth 2.0 / OpenID Connect：第三方认证授权协议，如微信、GitHub、Google 登录

### Token和JWT对比

| 维度         | Token                | JWT                        |
| ------------ | -------------------- | -------------------------- |
| 是否存服务端 | 是（如 Redis）       | 否（无状态）               |
| 信息内容     | 无内容，需查询数据库 | 自包含用户信息             |
| 实现复杂度   | 中等                 | 简单                       |
| 安全性       | 高（服务端控制）     | 中（加密、防篡改）         |
| 是否支持登出 | ✅ 立即删除           | ❌ 只能等过期或黑名单控制   |
| 适合场景     | 高安全、可控性强     | 分布式、微服务、跨服务传递 |
